# Intraday Portfolio

The intraday portfolio management system (`apps/engine/trading/intraday_portfolio.py`) handles persistent paper portfolio for the live intraday homepage trader. Key features include:

- **Target exposure**: 20% of total portfolio equity in SPY on BUY orders
- **Sell**: 100% liquidation of SPY position back to cash
- **Hold**: no position modification
- **Session gating**: real executions occur strictly during regular market hours (09:30 AM - 04:00 PM ET)
- **Dual execution**: records into Supabase ledger and mirrors to Alpaca paper account

The system enforces a strict 20% portfolio equity cap via `compute_intraday_trade_sizing()`, where BUY orders calculate the dollar deficit to reach 20% equity, and SELL orders liquidate 100% of currently held shares. Session gating ensures no trading occurs outside market hours.

## Alpaca Mirror (`_mirror_to_alpaca`)

The ledger commits first and is authoritative; the Alpaca mirror runs afterward purely to leave an external, un-editable record that the order was actually sent. `_mirror_to_alpaca(sb_client, broker, trade_id, ticker, quantity, signal, owner_id)` returns `(alpaca_order_id, alpaca_status)` and never raises or alters the ledger:

- Passes `guard_sells=False` to `AlpacaBroker.submit_market_order`, so a SELL is attempted in full even when the broker holds fewer shares than the ledger is selling — the broker's rejection (or the resulting short) is the audit record.
- `_broker_position_note` probes `try_get_alpaca_position` (evidence-grade: `None` when the broker cannot answer, `0.0` only for a genuine 404) and stamps `trades.alpaca_note` with `BROKER_POSITION_MISMATCH (ledger N, broker M)` when the broker genuinely holds fewer shares. A failed position read is never recorded as a 0-share book. The probe runs off the event loop via `asyncio.to_thread`, and the mismatch note is only written when the mirror status is **not** `ERROR` or `REJECTED` — in those cases the broker's own `alpaca_note` (the HTTP rejection/error reason) already explains the outcome and must not be overwritten.
- When the broker's own row write fails (`persisted: False`), the mirror retries once with `alpaca_status`, `alpaca_order_id`, and an explicit UTC `alpaca_submitted_at` — the reconciler filters on `alpaca_submitted_at`, so a SUBMITTED row without it could never advance to a terminal state.
- A missing broker records `alpaca_status = "DISABLED"` on the trade row; a broker whose Alpaca client is absent (missing keys / `ALPACA_ENABLED` off) returns `DISABLED` and the caller stamps it.
- The mirror outcome is returned as `alpaca_status` on the turn summary (`SUBMITTED` / `REJECTED` / `ERROR` / `SKIPPED_NO_POSITION` / `DISABLED`), so a rejected mirror is visible in the UI instead of silently reading `EXECUTED` with a null order id.

## Portfolio Initialization

`get_or_create_live_trader_portfolio()` looks up the live trader's portfolio by `owner_id` and, when none exists, inserts a fresh row seeded with `INITIAL_PORTFOLIO_CASH`. The initialization row does **not** pin a hardcoded `id` — the portfolio's primary key is generated by the database default, so each provisioned portfolio receives a real, unique identifier rather than a fixed constant. This keeps the ledger consistent with the database's own identity generation and avoids collisions across environments.
